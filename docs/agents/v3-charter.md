# MajsoulRPA v3 の方針

## 目的

v3 は、MajsoulRPA を一から設計し直すためのブランチです。v2 の README と
examples にある「利用者から見た感触」は参照しますが、API 名や互換性は
維持しません。内部実装はゼロから再設計します。

## 対象とする利用

MajsoulRPA は、Mahjong Soul (雀魂) の合意済み友人戦・大会で、ユーザーが
用意したボットや補助処理を参加させるための RPA フレームワークです。

対象ユーザーは大きく 2 種類です。

- フレームワークをそのまま使い、画面ごとのコールバック関数だけを登録する人
- Presentation や Sniffer 相当の拡張点を使い、未対応画面への対応、
  画面遷移の差し替え、通信保存などを行う人

## 対象外

以下は v3 でも実装しません。

- オープン対局、段位戦、未合意の対局への自動参加
- 規約違反や検出回避を主目的とする機能
- 認証情報、Cookie、アクセストークン、実メールをリポジトリ内に保存する仕組み
- ライブ通信 payload をテスト、フィクスチャ、examples、docs、コミットへ
  保存する仕組み
- 自動テストから実際の雀魂へアクセスする処理

## v2 から維持したい利用感

v2 の公開利用例から、次の体験を v3 でも重視します。

- ブラウザを動かすホストと RPA クライアントを分離できる
- ローカル一体構成でも動かせる
- ブラウザホストは CLI から起動できる
- RPA クライアントは async 関数で画面ごとの処理を登録できる
- 登録した Presentation だけが検出対象になる
- 任意の data をコールバック間で受け渡しできる
- Presentation を継承して、標準処理をスキップしたり画面操作を追加できる
- 通信キャプチャにユーザー処理を差し込める

## v2 から維持しないもの

次のものは維持前提にしません。

- パッケージ構造、モジュール名、クラス名
- private メソッドや private 属性
- 現在の sniffer プロセス構成
- 現在の config モデル分割
- 現在の template / region / delay の実装方式
- 現在の protocol 生成物の配置

必要性がある場合だけ、設計理由を明文化したうえで採用します。

## 資産の扱い

v2 の内容は一度すべて削除する前提です。スクリーンショット画像や `.proto`
ファイルなど、再利用や再取得が必要な資産は、必要になった時点でユーザーに
コミットを依頼します。エージェント判断で実ゲーム由来の画像、通信ログ、
生成 protocol ファイルを追加しません。
